# 室内雪迹清除机器人多模态感知与智能决策系统 V1.0

## 用户操作手册（待申请人核对的文档原稿）

本文对应当前项目中的 Python 上位机软件，不是机器人本体使用说明书。
本版本以虚拟 RGB-D 数据、模拟湿度、模拟定位和模拟执行器验证软件流程。
本文不证明实际清洁效率、识别准确率、现场安全性或真实机器人部署能力。
申请人应将原稿排版为实际需要的提交格式，统一软件名称、版本、页眉和页码。

## 1. 软件用途

软件用于室内雪迹、湿污清洁流程的感知与决策模拟，提供候选污染区域检测、
多模态评分、污染分级、任务管理、路径规划、清洁策略、复检补偿和运行监控。
主要使用者是机器人上位机软件开发、教学和联调人员。

系统不包含账号登录、在线服务、数据库管理或远程设备管理功能。
它通过本地命令行启动，通过 OpenCV 监控面板和结构化运行报告展示结果。
演示报告可在浏览器中离线查看，无需服务器或上传数据。

## 2. 运行条件与安装

- 建议 Python 3.10 及以上，安装 NumPy、OpenCV、PyYAML。
- 自动化验证还需要 pytest，具体依赖见项目根目录 requirements.txt。
- 当前开发机的解释器及依赖版本可在导出的 report.json 中查看。
- Mock 模式不需要相机、机器人、定位硬件或湿度探头。
- 如需实际弹出 OpenCV 窗口，必须具有可用的桌面显示环境和 GUI 版 OpenCV。
- 无桌面环境使用无窗口运行及离线面板截图导出功能。

在项目根目录打开终端：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py --help
```

下文命令均在项目根目录执行。Windows 使用相应虚拟环境中的 Python 路径；
本次检查并未验证 Windows 或树莓派的安装部署。

## 3. 基本巡检

```bash
.venv/bin/python main.py --mode mock --headless --steps 60 --json
```

启动后系统加载 config 目录配置、创建模拟接口、采集干净帧并建立参考图，
随后在 PATROL 与 DETECT 之间循环。默认场景为干净地面，tasks=0 是正常结果，
不能据此认为检测或清洁失效。若需要观察清洁闭环，请运行下面的指定场景。

--steps 是状态机步数上限，不是秒数；必须为正整数。
--headless 禁用窗口。默认行为也可由 config/system.yaml 的 headless 配置决定。
--json 将结构化结果输出到标准输出，过程日志和场景检查消息输出到标准错误。
正常运行返回码为 0，启动或运行失败返回非零，人工中断返回 130。

## 4. 运行完整清洁示例

```bash
.venv/bin/python main.py --scenario C
.venv/bin/python main.py --scenario C --json > scenario-C.json
```

场景 C 创建一处模拟中度污染。系统检测区域并取得空间位置，移动到采样点，
读取模拟湿度，计算融合评分并生成任务；规划路线后执行模拟清洁。
第一次复检不通过时进入 COMPENSATE，再次规划、清洁和复检，最终完成。
预期结果为 MEDIUM、retry=1、cleaning_passes=2、completed=1。

## 5. 八种演示场景

```bash
.venv/bin/python main.py --all-scenarios
.venv/bin/python main.py --all-scenarios --json > scenarios.json
```

| 场景 | 内容 | 预期结果 |
| --- | --- | --- |
| A | 干净地面巡检 | 无任务、无清洁动作 |
| B | 轻度污染 | 一次清洁、无补偿、任务完成 |
| C | 中度污染补偿 | 两遍清洁、一次补偿、任务完成 |
| D | 重度污染 | 首次按策略执行两遍清洁 |
| E | 无法清除的污染 | 有限次补偿后转人工检查，避免重复建任务 |
| F | 多目标任务处理 | 多个目标依次完成，每个任务恰好完成一次 |
| G | 路径不可达 | 记录无路径原因，进入 ERROR，安全停止模拟执行器 |
| H | 输入帧异常 | 记录异常，进入 ERROR，释放模拟资源 |

G/H 的 ERROR 是预设故障条件下的正确处理，不应作为正常成功清洁的截图。
F 不单独证明多个同时等待任务的优先级竞争顺序；该算法另有 tests/test_priority.py
覆盖评分、排序和防饿死。场景分级使用确定性提示值，不能作为真实识别效果的统计实验。

## 6. 一键生成演示与申报准备材料

```bash
.venv/bin/python -m tools.export_application_materials
```

工具自动创建新的 artifacts/copyright-时间戳 目录，不覆盖已有材料。
也可用 --output 指定尚不存在的输出目录。
导出过程实际执行 A–H，不连接或驱动任何真实机器人。

| 文件 | 使用方法 |
| --- | --- |
| index.html | 浏览器打开，查看场景说明、检查结果和实际生成的监控面板 |
| screenshots/*.png | 本次虚拟运行中按状态、任务和重试阶段导出的面板图 |
| report.json | 运行环境、场景检查、状态历史、逐步摘要和机器人动作日志 |
| source_full.txt | 固定文件顺序拼接的完整项目源码原稿，保留原始空行 |
| source_review.html | 每页 50 个非空源码行的打印整理稿，包含文件名和原文件行号 |
| manifest.json | 源码顺序、行数、SHA-256 及导出文件哈希，用于核对一致性 |
| USER_MANUAL.md | 本用户手册原稿 |
| COPYRIGHT_CHECKLIST.md | 申报缺项、权属与格式复核清单 |

截图左侧为最近一帧模拟 RGB 图及候选框，右侧为检测掩码；叠加区显示状态、
帧率、视觉/面积/污染评分、等级、任务编号、重试次数和路径长度（依阶段而定）。
无新采集的中间状态复用最近一帧，因此不应把截图理解为连续实时视频。
H 在首次检测就注入空帧，可能没有有效图像，其证据以报告中的错误与安全停止记录为准。

源码整理稿排除虚拟环境、第三方包、图片和 tests，保留项目业务及工具源码。
打印版只省略空白行，不修改非空代码内容；完整原稿仍可逐文件核对。
超过 60 页时，打印整理稿提取前、后各连续 30 页，否则全部保留。
当前模板采用 A4 横向小字号，仅用于整理审查，长行可能超宽；正式提交前应检查
打印预览、可读性、行数、连续性、结束页、软件名和版本，不要直接当作合格提交件。

## 7. 状态与结果解释

正常主要状态为 CALIBRATION、PATROL、DETECT、APPROACH、HUMIDITY_CONFIRM、
CLASSIFY、CREATE_TASK、PLANNING、NAVIGATING、CLEANING 和 RECHECK。
COMPENSATE 表示补偿清洁；MANUAL_CHECK 表示超过重试预算后需要人工处理；
ERROR 表示关键故障，系统停止继续执行；SHUTDOWN 表示资源已释放。

report.json 中 summary 是结束清理之前的运行快照，running=true 仅表示拍摄摘要时
系统仍处于可运行态，不代表命令退出后后台还在驱动设备。
trace 是逐步运行摘要，state_history 是状态迁移历史，robot_actions 是模拟动作日志。
passed 表示该场景的预设检查均成立，不等于真实硬件性能合格。

## 8. 参数配置

| 配置文件 | 内容 |
| --- | --- |
| config/camera.yaml | 图像尺寸、ROI、深度有效范围、参考帧标定 |

修改参数前保留原文件。修改后重新运行自动化测试和全部演示，重新导出材料。
不要用旧截图说明新版本，也不要通过修改评分提示值声称算法准确率提升。

## 9. 日志、退出与常见问题

运行日志保存在 logs，干净参考图保存在 data/clean_reference/reference.png。
日志包括状态、评分、清洁动作及异常原因；重复启动生成新日志。
按 Ctrl+C 中断运行后，程序尝试停止清洁、升起机构、停止移动并释放相机。
这些均为 Mock 动作，不能代替真实急停和安全认证。

- 默认无任务：默认地面干净，改用 --scenario B/C/D 观察任务。
- 没有窗口：headless 默认为 true；可先使用一键导出的离线 HTML 演示。
- 缺少依赖：确认使用 .venv 内解释器，按 requirements.txt 安装，不混用其他工程环境。
- pytest 被 ROS 插件干扰：可使用 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 再运行测试。
- 指定 real 失败：当前刻意拒绝 real 模式，尚未具备真实定位、外参、通信与执行器回执。
- 输出目录已存在：选择新目录，工具不会覆盖先前运行证据。
- 导出中途失败：遗留目录属于不完整材料，应排查后换新目录重试，不能直接提交。

## 10. 验证与使用边界

```bash
.venv/bin/python -m pytest -q
```

测试覆盖正常、边界和异常条件；最新测试数量以实际命令输出为准。
本次材料不包含真机验证。感知采用固定视角参考差分，对阴影、反光、曝光变化与
相机移动仍敏感；深度用于几何有效性，不直接测量湿度。
真实部署需要标定、真实定位、传感器适配、执行协议、到位回执、障碍处理和急停验证。
详细技术边界见项目根目录 DESIGN_REVIEW.md。
