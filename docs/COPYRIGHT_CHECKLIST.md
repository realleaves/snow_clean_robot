# V1.0 软著申请准备与缺项清单

本清单是基于项目检查整理的准备建议，不是法律意见或登记通过承诺。
查核日期：2026-10-23。实际申报方式、上传格式与补正要求以登记机构当前指引为准。

## 1. 当前判断

当前项目已有可运行的感知、融合、地图、任务、规划、策略、复检和监控代码，
可开始整理软件著作权登记材料。无需为了“看起来复杂”堆砌登录、数据库或神经网络。
这里证明的是虚拟上位机软件流程，不是实机清洁机器人已交付。
测试数量和代码行数不是登记通过标准，更不能替代权属核对。

## 2. 必须由申请人确认，不能自动生成

- [ ] 著作权人为个人、团队、学校还是其他单位；大创项目需核对任务书、资助协议、
  职务开发及合作开发约定。GitHub 账号、Git 作者邮箱不能证明法律权属。
- [ ] 全部实际开发者、合作开发协议及需要的授权；不得擅自省略共同权利人。
- [ ] 软件名称与版本最终定稿，申请表、手册、源码页眉与软件展示一致。
- [ ] 实际开发完成日期、是否发表、首次发表日期及地点；不得用本次检查日冒充完成日。
- [ ] 身份证明、任务书、归属协议、委托/合作/受让/许可文件（如适用）。
- [ ] 代码与图像来源核对，包括参考实现、复制片段、外部素材和辅助生成代码的使用情况；
  保留开发过程记录，不伪造独立开发经过或原创性证明。
- [ ] 申请表内容、签字/盖章及登记机构当前要求的其他证明。

建议沿用名称“室内雪迹清除机器人多模态感知与智能决策系统 V1.0”，同时在
功能说明中明确“当前交付为虚拟运行的上位机软件，硬件接口未完成实机适配”。
若最终改名，需要同步全部材料，不能只改申请表。

## 3. 已补的软件和材料准备能力

- [x] 修复带停止回调的场景结果不能 JSON 序列化的问题。
- [x] --json 标准输出为可直接解析的 JSON，检查消息与日志走标准错误。
- [x] 启动失败和运行故障返回非零；拒绝无效步数及相互冲突的命令组合。
- [x] 场景结果增加状态历史、逐步运行摘要和模拟机器人动作记录。
- [x] 实际运行生成监控截图、离线展示页、报告与环境版本信息。
- [x] 固定源码顺序与 SHA-256 清单，生成完整文本和分页整理稿，不打包第三方库。
- [x] 补充用户操作手册原稿和本清单。
- [x] 修正 F 场景原先无效的排序自比较，不再用它宣称验证多等待任务的优先级竞争。

## 4. 提交材料还需要人工排版与复核

国家版权局《计算机软件著作权登记办法》第九至十一条规定了申请表、鉴别材料与
相关证明文件；一般鉴别材料涉及源程序及一种文档的前、后各连续 30 页，不足
60 页的提交全部。除特定情况外，源程序每页不少于 50 行，文档每页不少于 30 行。
这不是“代码必须有 3000 行”或“手册必须凑够 60 页”。

- [ ] 检查 source_full.txt 与 manifest.json 是否对应准备冻结的代码版本。
- [ ] 检查 source_review.html 的页眉、页号、连续性、长行溢出、可读字号和结束页。
  它是打印整理稿，尚未对所有打印机、浏览器及最终上传格式作排版验收。
- [ ] 将 USER_MANUAL.md 配合真实生成的截图整理为所需文档格式。
- [ ] 文档与源码不足规定页数时提交全部，不靠重复代码、无意义注释或重复截图凑页。
- [ ] 明确截图是“虚拟运行监控面板”；没有有效帧的故障场景使用报告说明。
- [ ] 最终确认软件名称、版本、权利人、完成日期等在所有申请文件中一致。

## 5. 第三方依赖与来源

| 依赖 | 用途 | 处理要求 |
| --- | --- | --- |
| NumPy | 数组与数值计算 | 核对实际安装版本及其随包许可证、二进制依赖说明 |
| OpenCV Python | 图像处理与监控面板 | 核对具体发行包、版本及打包组件许可证 |
| PyYAML | 配置解析 | 保留使用版本与许可证信息 |
| pytest | 开发测试工具 | 不把测试框架源码当作自己的交存源码 |
| pyrealsense2 | 可选的真实相机适配依赖 | 当前虚拟验收不依赖；未验证设备采集 |

根目录没有显式项目许可证文件，这本身不能证明或否定申请资格。
不要为申请随意添加 MIT/GPL 声明；应由实际权利人决定授权方式。
一键工具仅收集项目约定目录内的 Python 源码，不证明其中每行的权属已获核验。
用户需要逐项核实外部代码及素材的来源与许可范围。

## 6. 不应写进成果描述的内容

- “已经完成真实 D435i、单片机、机器人本体与实机自主导航联调”。
- “真实雪迹识别准确率达某百分比”“现场清洁效率达到某百分比”。
- “多场景测试通过，因此所有环境安全可靠”“登记一定通过”。
- “必须训练 AI 模型/必须达到指定代码行数才可以登记”。

可以据实描述为：已实现基于虚拟 RGB-D 与湿度输入的污染检测、融合分级、任务管理、
A* 路径规划、模拟清洁、复检补偿和异常处理软件闭环，并提供可重复演示与测试记录。
